# 闲鱼订单与盈亏管理

## R — 原文 (Reading)

> 订单少的时候还能手动核对，订单多了之后简直爆单如上坟！……我会先建一张「商品表」……后面在「出单表」里新增订单时，不用每次重复复制货源信息……表格里提前建好的公式会自动算出利润和真实毛利率。
>
> — 海底桃，【工具】飞书多维表格 + 排版打印

---

## I — 方法论骨架 (Interpretation)

这套系统解决一个问题：**别被表面数据骗**（总订单多≠赚钱，营业额高可能是补单撑的）。两层结构：

1. **出单表（管过程）**：每单 8 字段——售货平台 / 订单状态（待发货·已发货·已签收）/ 订单类型（真实订单·补单，必须分开）/ 买家名（售后可搜）/ 商品信息 / 货源信息（采购链接+货源订单号）/ 物流信息 / 售后备注
2. **待发货视图（管执行）**：每天只处理未走完流程的单——去货源下单、回填单号、同步物流、备注异常；防漏发错发
3. **商品表联表（防重复劳动）**：SKU/商品名/货源平台/货源链接/默认成本维护一次，出单表选商品即自动带出，只需补实付款 → 公式自动算利润与真实毛利率
4. **每周复盘两张表（管判断）**：
   - SKU 盈亏表（按 SKU 汇总）：判断单品质量——真实单/补单数、货款毛利、毛利率；案例：毛利率 4.62% 的品单量再大也不值得推
   - 盈亏周表（按日期汇总）：判断经营健康——总订单/真实订单/补单/总营业额/真实营业额/总利润；案例：同样 77 单的两天，真实单 50 vs 43，利润差 300 元
5. **决策规则**：真实营业额低→查当天真实成交；货款成本高→查货源涨价或换品；补单成本高→控次日补单；总利润负→停掉"热闹但不赚钱"的品

## A1 — 应用示例 (Application Example)

### 示例: 2026/02/01 vs 02/03 盈亏周表对比
- **类型与来源**: 原书数据（【工具】盈亏周表）
- **输入**: 两天各 77 单
- **对比**: 02/01 真实单 50、真实营业额 3317.8、总利润 730.49；02/03 真实单 43、总利润 427.90
- **结论**: 表面相同（77 单），实际差 300 元利润——补单占比与真实成交决定真实健康度

### 示例: 先科烤箱 vs hosk1000W 的 SKU 盈亏
- **类型与来源**: 原书数据（【工具】SKU 盈亏表）
- **对比**: 先科烤箱 34 单（真实 23/补 11）毛利率 23.13% → 值得放量；hosk1000W 19 单（真实 10/补 9）毛利率 4.62% → 停止推广
- **结论**: 单量相近时，毛利率决定去留

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

- 订单渐多，靠脑子记状态开始出错（漏发/错发/忘记哪单是补单）
- 月底算账发现利润和感觉对不上，怀疑被补单和成本吃掉
- 想判断某个品该继续推还是停掉

### 语言信号 (用户的话里出现这些就应激活)

"订单一多就乱" / "分不清哪单是补单" / "利润算不清" / "哪个品赚钱" / "要不要停掉这个品" / "怎么用飞书表格管理订单" / "复盘"

### 与相邻 skill 的区分

- 要不要补单、怎么补 → growth-ops；本 skill 只管记录与判断
- 单品定多少钱 → pricing-profit；本 skill 验证定价是否兑现

## E — 可执行步骤 (Execution)

0. **执行前对齐**（缺任一项先向用户要，不要猜）
   - 用户表格工具（飞书多维表格最佳；Excel/Notion 可平替但公式要手改）
   - 当前痛点是"过程乱"还是"算不清钱"（前者先建出单表，后者先建复盘表）
   - 补单是否已是既成事实（是→订单类型字段必填；否→保留字段备用）
   - 完成标准: 三项对齐，产出物口径确定为「表结构 + 配置说明 + 复盘清单 + 去留规则」

1. **建商品表**
   - 字段：SKU、商品名、货源平台、货源链接、默认成本、（可选）当前售价
   - 完成标准: 在售商品全部录入

2. **建出单表（8 字段 + 联表）**
   - 商品信息字段关联商品表（自动带出成本/货源链接）；公式：利润 = 实付款 − 默认成本 − 手续费(0.6%) −（补单成本，若订单类型=补单则计）
   - 完成标准: 手动只填「订单状态/类型/买家名/实付款」，其余自动

3. **建待发货视图**
   - 筛选：订单状态 = 待发货；按下单时间倒序
   - 完成标准: 每天打开先看此视图，处理完一单改一个状态

4. **建复盘模板（排版打印或表格透视图）**
   - SKU 盈亏表：按 SKU×订单类型汇总，输出毛利率
   - 盈亏周表：按下单日期汇总，输出真实营业额/总利润
   - 完成标准: 两张表能一键/半自动生成

5. **套用决策规则**
   - 毛利率 <10% 且补单占比 >40% → 亮红灯（评估停推）
   - 补单成本环比上升 → 次日降补单量
   - 总利润为负 → 停掉该品，流量让给健康品
   - 完成标准: 给出本周各品的红绿灯结论

6. **节奏固化**
   - 每天 1 分钟：新订单入表 + 状态流转；每周一次：复盘两表 + 决策
   - 完成标准: 用户确认节奏可坚持（原书：建表麻烦是心理门槛，实际每单只多 1 分钟）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 日订单 <5 单——手动翻闲鱼后台更快，建表收益还撑不起维护成本（原书亦承认"订单少时手动核对"可行）
- 需要多店铺合并报表——原书方案单店视角，多店需自行加「店铺」维度

### 作者在书中警告的失败模式

- 真实单和补单混记 → 一切分析失真（本表第一原则）
- 只看总订单数/总营业额 → 被补单和货款成本吃掉利润而不自知
- 月底才算账 → 错过止损窗口（"不用到月底才知道哪里做错了"）

### 作者的盲点 / 时代局限

- 方案绑定飞书生态（多维表格+排版打印），迁移到其他工具需重做公式
- 未覆盖库存对账（无货源模式基本无库存，但退款中的在途资金未建模）
- 退货损耗未单列字段（只进售后备注），精细核算需自行加列

### 容易混淆的邻近方法论

- 财务记账（复式记账）——本表是运营视角的轻量流水，非会计口径
- BI 看板方法论——同源思想（过程指标×结果指标），但本 skill 是个人卖家可落地的最小方案
