# 闲鱼店铺搭建

## R — 原文 (Reading)

> 「一机一卡一号一网」，也就是一个手机装一张电话卡，对应一个闲鱼账号，每个账号一个网络。不要在一台设备上频繁切换账号……这些都会导致平台检测到异常并限流。
>
> — 海底桃，【一】店铺搭建

---

## I — 方法论骨架 (Interpretation)

搭建期的目标只有一个：让平台相信你是「一个正常的专业卖家」。分四层：

1. **账号数量**：1 身份证 = 3 支付宝 = 3 闲鱼店（芝麻分共享）；新手只做 1 个号——把一个做起来再开下一个，避免重复犯错
2. **设备环境**：一机一卡一号一网；禁忌：同设备频繁切号、同账号频繁切设备、一个 WiFi 多账号——都会触发风控限流。多店铺的组合：手机+WiFi / 手机+流量 / 平板+流量
3. **信用门槛**：芝麻信用 ≥「良好」；不足就先养支付宝（多付款、扫共享单车/售货机）
4. **人设包装**（让店铺像专业卖家）：性别建议填女（买家信任倾向）；昵称带品类词（XX 数码/XX 游戏）且 30 天只能改一次——先定类目再改名；头像用真人感/门店感照片；简介写「实体店店主/厂家直营 + 清仓特价、一件也是批发价」；生日/院校/常住地都填上增加可信度
5. **鱼小铺**：领域选定后改起来慢且影响推流方向——确定品类后再开通，「领域」选目标品类，身份选「实体店主」或自定义「源头工厂」

## A1 — 应用示例 (Application Example)

### 示例 1: 新手双号翻车
- **类型与来源**: 原书反例（【一】店铺数量）
- **问题/输入**: 新手同时开 3 个号齐头运营
- **方法论的使用**: 反面教材——错误的方法被重复 3 次
- **结论**: 3 个号一起死
- **结果**: 原书建议：先做 1 个号，跑通后再复制

### 示例 2: 人设包装前后对比
- **类型与来源**: 原书方法（【一】账号设置）
- **问题/输入**: 新号默认设置（无昵称意义/无简介）vs 包装后
- **方法论的使用**: 昵称"XX 数码"（等确定卖数码再改）；简介"实体店店主，清仓特价，一件也是批发价"；资料全填
- **结论**: 主页观感从「路人出闲置」变成「专业卖家清仓」
- **结果**: 初始信任度提升（教程【五】：用户点进主页一看就是专业卖家才敢下单）

## E — 可执行步骤 (Execution)

**必需输入**: 现有支付宝/闲鱼账号情况；计划投入设备数量；是否已定品类（影响昵称与鱼小铺）
**交付物**: 开店配置检查清单（可勾选）

1. **账号盘点**
   - 确认支付宝实名状态与芝麻分（≥良好）；不达标先养号 1~2 周
   - 完成标准: 1 个主账号确定；多号计划标注为「二期」

2. **设备网络绑定**
   - 一机一卡一号一网；检查当前设备是否有其他闲鱼账号登录痕迹
   - 完成标准: 账号-设备-网络一一对应，无共享

3. **基础设置**
   - 绑定实名、关闭隐私暴露项（如位置精确显示）
   - 完成标准: 账号可正常收付款

4. **人设四件套**
   - 性别：女（无论真实）；昵称：品类词（未定品类先不改，30 天一次机会）；头像：真人感/门店感；简介：身份+优势词
   - 完成标准: 主页整体观感通过「专业卖家」测试

5. **资料补全**
   - 生日/喜欢的/院校/常住地全填
   - 完成标准: 个人资料页无空项

6. **鱼小铺决策**
   - 已定品类 → 开通，领域选品类，身份「实体店主/源头工厂」
   - 未定品类 → 推迟，先选品（product-selection）后再回来
   - 判停条件: 类目未定则跳过本步，不强行开通

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 账号已被严重处罚（封禁级）→ 先申诉/换身份，配置无意义
- 只出个人闲置不开店——用默认账号即可，无需人设包装

### 作者在书中警告的失败模式

- 一上来开多号 → 错误方法重复 N 次
- 同 WiFi 挂多号 / 频繁切设备 → 风控限流
- 昵称先随手起——30 天改一次，类目变了昵称卡死
- 鱼小铺领域乱选 → 推流方向错 + 改动有冷却期

### 作者的盲点 / 时代局限

- 「性别填女」是信任 hack，若类目用户以男性为主可能反直觉（原书未讨论）
- 平台风控规则（设备指纹细节）不透明，规则为经验总结

### 容易混淆的邻近方法论

- 淘宝天猫开店流程（保证金/资质）——闲鱼个人店零门槛，完全不同
- 多平台矩阵运营——本方法聚焦闲鱼单平台规则
